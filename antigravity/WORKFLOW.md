# Anti-Gravity Development Workflow

لكل طلب تطوير:

### Phase A — Inspect
- اقرأ الملفات المرتبطة.
- حدد dependencies.
- حدد architecture.
- ابحث عن كود مشابه قبل إنشاء كود جديد.

### Phase B — Plan
اكتب خطة قصيرة:
1. الملفات التي ستتغير.
2. سبب كل تغيير.
3. الاختبارات المطلوبة.

### Phase C — Implement
- نفّذ أقل تغيير يحقق المطلوب.
- حافظ على API الداخلية قدر الإمكان.
- لا تكسر الميزات الموجودة.

### Phase D — Validate
- format
- analyze
- tests
- راجع RTL/LTR إذا كانت المهمة UI.

### Phase E — Report
أظهر:
- ما تم تغييره.
- الاختبارات التي تم تشغيلها.
- أي مشكلة متبقية.
- أي قرار يحتاج موافقة.

لا تقل "تم" إذا كانت الاختبارات الأساسية فاشلة.
